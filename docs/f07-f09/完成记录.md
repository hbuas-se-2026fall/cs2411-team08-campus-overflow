## 2. 本次完成内容

### F07：投票、采纳与认证

- 问题和回答投票显示当前用户选择，快速重复点击期间禁用按钮。
- 投票先更新当前页面；请求失败时恢复原票数和原选择，请求成功后重新读取详情。
- 提问者可采纳、更换采纳或撤销采纳；更换和撤销均显示确认说明。
- AI 原始回答不显示人工投票和采纳奖励入口。
- 课程管理者可认证回答，并可填写原因撤销认证。
- 教师复核入口按 `canReview` 与独立版本字段控制，不复用提问者采纳操作。
- 所有状态变更后重新读取问题、回答、采纳、认证和悬赏状态。

### F08：个人主页、声誉、积分与排行榜

- 新增 `/users/:userId` 个人主页，展示基本资料、身份认证、学院、加入时间、声誉和徽章。
- 本人主页显示 `/me/points` 入口；他人主页不读取或显示私有积分余额。
- 新增本人积分与声誉流水页，分别展示可用积分、冻结积分和声誉。
- 声誉流水支持分页，显示事件、变化值、关联对象和时间；负值明确标识为冲正或扣减。
- 排行榜增加加载、失败、空数据状态、统计周期说明和个人主页链接。
- 导航栏用户昵称、问题作者和回答作者均可进入个人主页。

### F09：悬赏发布与结算展示

- 以正式对话框替换简单输入方式，字段为悬赏积分和有效天数。
- 前端边界与接口一致：积分 10–500，天数 1–14。
- 对话框展示本人可用积分、冻结/结算规则与提交状态；失败时保留输入。
- 详情展示发布者、积分、截止时间、后端状态及获奖回答链接。
- OPEN 状态显示剩余时间；到期后重新查询后端，不由浏览器自行结算。
- 发布成功后重新查询悬赏和本人余额。
- 发布请求超时时先查询当前悬赏；仅在确认未创建时提示用户决定是否重试。

## 3. 后端契约核对与限制

本次只调用仓库中已经声明的接口，没有虚构接口：

- 已接入：投票、采纳、撤销采纳、回答认证、撤销认证、个人资料、声誉档案、声誉流水、排行榜、悬赏查询和发布。
- 举报：仓库当前没有举报接口，因此未显示无法提交的举报按钮。
- 教师采纳复核：接口要求 `expectedVersion`，但问题详情当前未返回版本号；前端入口只有后端返回版本号时才出现，避免发送错误版本。
- 认证详情：回答详情当前只返回认证者，不返回认证时间和适用回答版本，因此当前只展示认证者。
- 用户提问/回答：当前没有按用户查询两类列表的接口，个人主页明确显示接口限制，不进行当前页数据拼接。
- 积分流水：当前只提供声誉流水，没有独立积分收支流水和类型筛选接口；页面不把声誉流水冒充积分流水。
- 课程范围排行榜：当前排行榜接口只支持时间周期，不提供课程参数，因此只展示全平台时间榜。
- 悬赏、声誉和排行榜的应用服务仍含后端后续阶段 TODO；前端已按控制器契约完成，真实数据与结算依赖对应后端阶段完成。

## 4. 运行过程

1. 获取远端最新 `main`，确认 PR #7 已合并 F04–F06。
2. 从 `origin/main` 创建并切换分支 `f07-f09`。
3. 阅读四份项目文档的 F07–F09 要求，并核对仓库控制器、视图类型和权限字段。
4. 修改前端类型、请求封装、路由、问题详情、排行榜和样式；新增个人主页与积分/流水页。
5. 执行 TypeScript 类型检查：

   ```text
   tsc --noEmit
   ```

6. 执行 Vite 生产构建：

   ```text
   vite build
   ```
