## 背景与目标

B01 的六条要求中，工程已有相当好的基础（统一异常映射、事务性发件箱、登录限流、会话轮换均已存在），本批定位是**补齐缺口**而非重建：

1. 请求全链路可追踪（requestId + 日志关联）；
2. 异常映射补 404/405/400 兜底，且不泄露敏感信息；
3. 业务幂等键基础设施（供后续扣款/悬赏/AI 生成使用）；
4. 可靠异步任务落库（替代「只在内存或裸 `@Scheduled`」）；
5. 权限缓存失效机制；
6. 内部服务调用认证（供 Python AI 服务回调）。

**明确不做**（防范围蔓延）：不新建限流框架、不改现有 outbox / 对账的 `@Scheduled`、不提前给资源加能力字段、不引入新依赖、不动前端与既有测试断言。

## 数据库变更

`V202611040001__platform_b01_foundations.sql`（平台级表，不属于任何限界上下文）：

- `co_command_result`：`idempotency_key`（主键）、`status`(RUNNING/SUCCEEDED)、`result_json`、`created_at`、`expires_at`，索引 `idx_cmd_result_expiry`。推荐与业务副作用同事务使用，命令失败时占位行随事务回滚可安全重试。
- `co_async_task`：`id`、`task_type`、`biz_key`、`payload`、`status`(PENDING/RUNNING/SUCCEEDED/DEAD)、`attempts`、`max_attempts`、`next_run_at`、`locked_until`、`locked_by`、`last_error`、时间戳；`UNIQUE(task_type, biz_key)` 天然防重复入队，索引 `idx_async_task_pending`。

## 设计决策

- **W3 分页约定**：核对发现 `shared/page/PageRequest` 已实现 `1 ≤ size ≤ 50` 的收窄，**无需改动**；只把「列表一律 `PageResult`、筛选在 SQL 层」写进约定，避免 YAGNI。
- **W4 细分能力**：只出约定（查询视图内嵌 `canXxx` 布尔字段、由应用层组装、领域层不感知 HTTP），不提前建空转工具类，随 B03/B04 落地。
- **DIP / 六边形**：业务侧只依赖 shared 的端口接口，JDBC/Redis 实现全部放 bootstrap，构造注入。
- **KISS**：请求追踪用自写 Filter（不上 Micrometer Tracing）；异步任务用 MySQL 表（不上消息队列）；处理器经 `ObjectProvider` 注入，避免空列表导致启动失败。
- **不重复造轮子**：outbox（`OutboxIntegrationEventPublisher` + `OutboxRelay` + `ProcessedEventStore`）已完整，本批不动；幂等与任务表沿用其租约/清理模式（DRY）。
