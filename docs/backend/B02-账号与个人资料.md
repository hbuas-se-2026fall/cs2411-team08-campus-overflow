## 背景与目标

调研结论：**约 80% 能力已存在**，全部是复用项——学生注册（`User.register()` 角色硬编码 `Role.STUDENT`，请求体无角色字段故不能越权）、教师/助教由管理员创建、BCrypt 密码哈希、登录失败限流（`RedisLoginThrottle` 1 分钟窗口 5 次）、认证审计、会话 ID 轮换（`changeSessionId()`，Redis 服务端会话）、`GET /auth/me` 的 `MeView`、平台角色与课程角色分离、登出失效。

**真实开发量 = 两个 profile 端点 + 一个领域方法 + 一个限流增强**：

1. 个人资料修改（仅允许字段、仅本人）；
2. 公开主页与本人私有视图分离（单端点、单 DTO）；
3. 登录限流时返回剩余等待秒数（前端 F02 要求「显示后端可提供的等待信息」）。

不碰注册/登录/会话主干；email 修改、头像、找回密码均不做（YAGNI，计划未要求）。

## API 变更

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/users/{id}/profile` | 任意登录用户可查公开主页；未登录由安全链 401 |
| `PUT` | `/api/v1/users/me/profile` | 仅本人；请求体 `{displayName, college, className}`，字段级 `@Size` 校验 |

路由无冲突：`/users/me/profile` 仅 PUT，`/users/{id}/profile` 仅 GET，且 `{id}` 为 long，`me` 不会被匹配。

`ProfileView` 视图裁剪：**不返回** email、username（登录凭据）、className（半隐私）、余额/积分流水（属 reputation 上下文）。本人查看时通过 `self` 子对象返回私有三字段。

## 错误码

| 码 | 状态 | 语义 |
| --- | --- | --- |
| `ID-2007` | 409 | 昵称已被使用（displayName 唯一性冲突） |
| `ID-429-THROTTLED` | 429 | 登录失败次数过多，响应含 `retryAfterSeconds` |

## 设计决策

- **SRP**：命令归 `UserProfileService`、查询归原有 `UserQueryService`，profile 逻辑不塞进 `AuthController`。
- **OCP**：`ProfileView.self` 用可空子对象，而不是「两个端点 + 两套 DTO」；未来加私有字段不改老结构。
- **DIP**：`UserController → UserProfileService → UserRepository` 端口，构造注入。
- **POLA / 最小权限**：管理员不代改他人资料（计划只说「本人允许字段」）。
- **KISS / YAGNI**：email 不开放（涉及验证流程）、公开视图不显示 className；429 + `retryAfterSeconds` 用标准 HTTP 语义而非自定义码。
