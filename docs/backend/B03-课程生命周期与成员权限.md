## 背景与目标

课程 CRUD 已存在（创建、code+term 复合唯一、目录/我的课程、直接加入、任命助教、跨课程隔离），**缺口集中在「权限与生命周期」**：

1. `GET /courses/{id}/members` 无 Actor 校验——任何登录用户凭课程 ID 可拉全名单（任务要求点名补齐）；
2. 成员无「有效/移除」状态、无移除端点；
3. 课程无开放/归档状态，归档只读无从谈起；
4. 已移除成员不能继续读私有内容（需成员状态 + 权限缓存失效联动）；
5. 缺「离开课程」端点。

## API 变更

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/courses/{courseId}/members` | **补授权**：仅课程成员或平台管理员 |
| `POST` | `/api/v1/courses/{courseId}/leave` | 离开课程（与 `join` 对称） |
| `DELETE` | `/api/v1/courses/{courseId}/members/{userId}` | 移除成员 |
| `PUT` | `/api/v1/courses/{courseId}/status` | `{status: OPEN\|ARCHIVED}`，归档/重开 |

路由决策：离开课程**不用 `DELETE /{courseId}/members/me`**——`me` 会被 `{userId}`(long) 匹配导致 400 而非语义正确；改用 `POST /{courseId}/leave`，与 `join` 对称且更清晰。

## 数据库变更

`V202609010101__identity_course_lifecycle.sql`：

```sql
ALTER TABLE id_course
    ADD COLUMN status VARCHAR(16) NOT NULL DEFAULT 'OPEN';
ALTER TABLE id_course_member
    ADD COLUMN status VARCHAR(16) NOT NULL DEFAULT 'ACTIVE',
    ADD COLUMN removed_at DATETIME(6) NULL;
CREATE INDEX idx_member_course_status ON id_course_member (course_id, status);
```

存量数据默认 `OPEN` / `ACTIVE`，无需回填。

## 错误码

| 码 | 语义 |
| --- | --- |
| `ID-3004` | 非课程成员/管理员读取成员名单（403） |
| `ID-1014` | 教师本人不可被移除 |
| `ID-1015` | 教师不可退出自己创建的课程 |

（其余课程相关码 `ID-2004` 同学期代码唯一、`ID-2005` 重复加入、`ID-1013` 教师角色不可降级、`ID-3002/3003` 创建/任命权限均为既有实现。）

## 设计决策

- **软删除 + 复活**（符合项目软删除 ADR）：成员移除不删行，保留 `removedAt` 痕迹；重新加入复用原行改为 ACTIVE。
- **归档可逆**：`archive` / `reopen` 是状态调整而非删除；归档只读通过 `CourseSummary.status` 发布给 B04/B05 消费（跨上下文只经 `*.api`，FF-5 用 String 传递）。
- **权限失效联动**：成员移除/角色变更/加入/离开后 `PermissionCache.evictAll(userId)`（版本号 bump，全局缓存 ≤5min TTL 兜底）。成员变更低频，全局失效代价可接受，**不做 per-user 精细失效**（YAGNI，等 B04 真实接消费方再评估）。
- **POLA / 最小权限**：TA 不可移除人；教师本人不可被移除、不可退出（所有者必须走转让/归档，首版不做转让）。
- **DRY**：`requireCourseManager` 私有方法统一课程归属判定，新建的归档/移除动作复用既有规则。
